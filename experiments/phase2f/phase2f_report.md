# Phase 2F: Evaluator and Gatekeeper Hardening

## 1. Why Phase 2F exists
The independent Gemini audit of Phase 2E exposed two critical weaknesses in the experimental harness. First, the Case A evaluator was overly strict, requiring an exact string match ("Product Thumbnail") which unfairly penalized valid semantic text generated by the higher-capacity model. Second, the Case C gatekeeper failed to validate the syntax of the `newNode` property for `REPLACE_NODE` operations, allowing malformed HTML to pass into the AST patcher and cause build failures. This phase hardens the testing architecture without running a new model experiment.

## 2. Case A Evaluator Problem
The previous evaluator enforced exact string equality: `actual === expectedGroundTruth`. This is an inappropriate metric for an independent reasoning model operating without access to the hidden ground-truth expectation. The 14B model successfully added an `alt` attribute that mechanically solved the Axe violation but was rejected for not predicting the exact phrase.

## 3. New Evaluator Definition
The evaluator has been updated to use a bounded semantic validity check:
```javascript
if (typeof actual !== 'string') {
    semanticPass = false;
} else {
    const trimmed = actual.trim();
    const lower = trimmed.toLowerCase();
    const antiPatterns = ["image", "picture", "photo", "image of an image", "placeholder"];
    if (trimmed === "") {
        semanticPass = false;
    } else if (antiPatterns.includes(lower) || lower.startsWith("image of ") || lower.startsWith("picture of ") || lower.startsWith("photo of ")) {
        semanticPass = false;
    } else {
        semanticPass = true;
    }
}
```

## 4. Case C Gatekeeper Problem
The V0 `REPLACE_NODE` operation explicitly expects `newNode` to contain a valid tag name (e.g., `"p"`). In Phase 2E, the higher-capacity model generated raw HTML (`"<p>System Maintenance at Midnight</p>"`). The previous gatekeeper only checked `op.newNode === 'marquee'`, missing structural tag validation. This allowed the string to reach the Babel patcher, where it caused a JSX syntax error (`[builtin:vite-transform] Unexpected token`).

## 5. New Gatekeeper Definition
The gatekeeper now enforces strict structural requirements for `newNode`:
```javascript
if (typeof op.newNode !== 'string') return { ok: false, reason: 'newNode must be a string' };
const trimmedNode = op.newNode.trim();
if (!/^[A-Za-z][A-Za-z0-9:-]*$/.test(trimmedNode)) return { ok: false, reason: 'newNode must be a valid HTML/JSX tag name without markup' };
```

## 6. Negative Tests
The updated gatekeeper correctly rejects the following inputs:
- `<p>System Maintenance</p>`
- `<p>`
- `</p>`
- `p>`
- `<p`
- `p text`
- ` ` (whitespace)
- `""` (empty string)

The updated evaluator correctly rejects the following inputs:
- `""` (empty string)
- `   ` (whitespace)
- `image`
- `Picture`
- `PHOTO`
- `Image of a dog`
- `picture of sunset`
- `placeholder`

## 7. Positive Tests
The updated gatekeeper correctly accepts the following valid JSX tags:
- `p`
- `strong`
- `section`
- `my-custom-element`

The updated evaluator correctly accepts non-generic descriptive text:
- `Product Thumbnail`
- `Dog playing fetch`
- `A chart showing sales growth`
- `Descriptive text here`

## 8. Regression Results
All automated tests, typechecks (`npx tsc --noEmit`), and build routines (`npx vite build`) pass cleanly. The architectural improvements do not weaken existing security controls.

## 9. Phase 2E Historical Integrity
- Phase 2A through 2D remain unchanged.
- Phase 2E raw artifacts (payloads, raw results) are preserved exactly as they executed.
- The Phase 2E report was updated strictly to distinguish the original mechanical performance from the post-hoc harness limitations (labeling Case A as an evaluator limitation and Case C as exposing a gatekeeper gap).

## 10. Remaining Limitations
The fine-tuned schema remains highly rigid. The architectural failure on Case C (hallucinating full HTML markup for `REPLACE_NODE`) highlights a continuing structural limitation in zero-shot capability when mapping free-form frontier-model reasoning into strict AST operations.
