# Phase 2F: Evaluator and Gatekeeper Hardening

## 1. Why Phase 2F exists
The independent Gemini audit of Phase 2E exposed two critical weaknesses in the experimental harness. First, the Case A evaluator was overly strict, requiring an exact string match which unfairly penalized valid text generated by the higher-capacity model. Second, the Case C gatekeeper failed to validate the syntax of the `newNode` property for `REPLACE_NODE` operations, allowing malformed HTML to pass into the AST patcher and cause build failures. This phase hardens the testing architecture without running a new model experiment.

## 2. Case C Security Hardening
The previous gatekeeper used a regex-only approach (`^[A-Za-z][A-Za-z0-9:-]*$`) which was insufficient because it permitted dangerous executable/framework tags (such as `script`, `iframe`, `object`, `embed`, etc.).

The gatekeeper was updated to replace regex-only acceptance with a strict semantic allowlist. The allowlist is restricted to non-executable semantic/presentation elements justified for accessibility remediation, including:
`p, span, div, button, strong, em, h1, h2, h3, h4, h5, h6, section, article, aside, main, header, footer, nav, ul, ol, li, blockquote, label, a, form, fieldset, legend, details, summary`

It explicitly rejects dangerous tags case-insensitively, including: `script, iframe, object, embed, style, link, meta, base, svg, html, head, body`. It also rejects malformed input containing `<`, `>`, `/`, whitespace, raw HTML, and namespace syntax.

Positive tests confirm that safe tags (`p`, `span`, `div`, etc.) are accepted.

## 3. Case A Terminology Calibration
The previous documentation for Case A used terms like "semantic validation" and "semantic ground truth", which are inappropriate for the current heuristic.

The Case A evaluator provides bounded heuristic validation / anti-pattern rejection. It does not establish semantic correctness of alt text. It only verifies that the alt text exists, is non-empty, and avoids known generic anti-patterns (e.g., "image", "picture", "placeholder").

## 4. Phase 2E Causal Classification
The historical chain of the original Phase 2E result for Case C is preserved exactly:
`14B model -> malformed REPLACE_NODE proposal -> previous gatekeeper accepted malformed value -> patcher received invalid AST argument -> build failure`

**PRIMARY ISSUE**: Gatekeeper validation gap / interface-contract failure.
**DOWNSTREAM EFFECT**: Patcher/build failure caused by invalid input admitted by the previous gatekeeper.

This establishes that the failure was not a patcher limitation, but rather a gatekeeper limitation that allowed invalid input to be admitted.

## 5. Security Regression Tests
All new Case C and Case A unit tests passed. We verified dangerous tag rejection, malformed tag rejection, valid tag acceptance, existing unsafe-operation rejection, `NODE_A` enforcement, operation-count enforcement, and `SAFE_ABORT` behavior.

Build and typechecks (`npx tsc --noEmit` and `npx vite build`) passed without errors.
