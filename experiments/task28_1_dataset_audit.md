# Task 28.1 Dataset Audit Report

This report provides an independent audit of the synthetic accessibility remediation dataset generated in Task 28 before any QLoRA training.

## 1. CLOSED-LOOP VERIFICATION
**Result:** **PASS (with limitations)**
**Evidence:** The generator explicitly executes `validateProposalBundle` and `applyPatchBundle` from the production `pipeline_v6.js` against an active temp file, followed by reparsing the AST and asserting invariants.
**Limitation:** It verifies that the intended defect was cleared, but it does not run a comprehensive baseline diff (see Global Regression). However, the core closed-loop patch validation works correctly.

## 2. GLOBAL REGRESSION
**Result:** **FAIL**
**Evidence:** The verification function checks if the target Axe violation was cleared: 
```javascript
if (patchedAxe.includes(ex.expectedViolation)) { return { valid: false ... } }
```
It **does not** verify if new, unrelated violations were introduced (e.g., it does not compare `validAxe.length` to `patchedAxe.length`). If a patch accidentally breaks another part of the tree, this generator will still accept it as long as the original targeted violation disappears.

## 3. SAFE_ABORT
**Result:** **PASS**
**Evidence:** The generator produces explicit, deterministic scenarios for `SAFE_ABORT`. 
*Example evaluated:* 
```markdown
NODE_A:
<div id="id-5bho" onClick={() => {}} className="submit-btn">Profile</div>
PARENT:
<form>...</form>
```
*Rationale:* "Changing to button inside form could trigger unintended submits."
This is a mathematically sound, deterministic reason for an abort. The provided context boundary explicitly includes the `<form>...</form>` parent, giving the model the exact information required to deduce the abort independently.

## 4. FINGERPRINTING
**Result:** **PASS**
**Evidence:** The `generateFingerprint(ast)` function uses Babel's AST traversal to build a normalized string. It ignores text nodes, variable names, and class names, preserving only the tag hierarchy and critical attributes (`role`, `aria-*`, `type`, `alt`, `tabIndex`). This ensures genuine subtree comparison rather than brittle text matching.

## 5. TASK 27 LEAKAGE
**Result:** **PASS**
**Evidence:** The generator parses `Task18Benchmark.tsx`, traverses its exported components, and computes their normalized structural skeletons. Every synthetic candidate is checked against this protected set. 
- Protected structure count: 12
- Final dataset leakage count: 0 
All structural overlaps with Task 27 were strictly blocked prior to acceptance.

## 6. SAMPLE QUALITY
**Result:** **PASS**
**Evidence:** I inspected 10 random examples from `train.jsonl` across all categories. 
- Context is minimal and matches the runtime boundary (`NODE_A`, `NODE_B`, `PARENT`). No file paths or line coordinates leak into the prompt.
- `rationale` is concise and strictly limited to a single sentence (e.g., "Label must be associated with input."). There is no hidden chain-of-thought.
- The assistant payloads match the strict JSON schema enforced by `pipeline_v6.js`.

## 7. SPLIT INTEGRITY
**Result:** **FAIL**
**Evidence:** The dataset splits (`train.jsonl`, `validation.jsonl`, `test_internal.jsonl`) are generated by randomly shuffling the total accepted pool (`allValid`). Because the generator uses a `DIVERSITY_CAP = 3`, there are up to 3 instances of the same normalized structural skeleton in the pool. Random shuffling guarantees that identical structural skeletons will bleed across the train and validation splits, causing train-test contamination. 

## 8. FINAL CONCLUSION

The dataset generation architecture is incredibly robust regarding patch syntax, schema conformity, and Task 27 isolation. However, the lack of strict Global Regression checks during patch verification and the train-test contamination of structural skeletons mean the dataset is not ready for a valid scientific training run.

**DATASET NOT YET APPROVED**
